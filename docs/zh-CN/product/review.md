# 社区审核

---

## 审核机制

TinyForum 采用 **自动审核 + 人工审核** 相结合的内容治理模式。

### 内容状态流转

```
发布 → pending（待审核）→ approved（通过）/ rejected（拒绝）
                              ↓
                        published（已发布）
```

### 自动审核触发条件

- **敏感词命中**：DFA 算法匹配到敏感词时，自动将帖子标记为待审核
- **LLM 复核**：敏感词命中后，通过 AI 模型二次判断上下文语义，降低误判
- **新用户风控**：新注册用户前 N 条帖子强制进入审核队列
- **高风险行为**：IP/用户风险评分超阈值时自动拦截

### 审核操作

| 操作 | 说明 | 权限 |
|------|------|------|
| 审核通过 | 帖子进入公开可见状态 | reviewer+ |
| 审核拒绝 | 帖子不展示，通知作者原因 | reviewer+ |
| 内容隐藏 | 临时隐藏帖子（不删除） | moderator+ |
| 帖子锁定 | 禁止新评论 | moderator+ |
| 帖子删除 | 逻辑删除（软删除） | admin+ |

### 审核后台

管理员/审核员通过审核后台 (`/admin/review`) 进行内容审核：

- 待审核队列列表
- 帖子内容预览（含敏感词高亮）
- 一键通过/拒绝
- 批量操作
- 审核历史记录

## 举报系统

用户可通过举报功能参与社区治理：

```
POST /api/v1/reports
```

| 字段 | 说明 |
|------|------|
| `target_type` | 举报目标类型（post / comment） |
| `target_id` | 目标 ID |
| `reason` | 举报原因 |
| `description` | 详细说明（可选） |

### 举报处理流程

```
用户举报 → 系统记录 → 审核员审查 → 处理（忽略/警告/删帖/封禁）
```

- 同一用户对同一目标只能举报一次
- 被多次举报的内容自动提升优先级
- 处理结果通过系统通知告知举报者

## 违规与惩罚

### 违规类型

| 类型 | 说明 | 触发条件 |
|------|------|----------|
| 垃圾广告 | 发布推广、广告内容 | 敏感词/举报 |
| 人身攻击 | 辱骂、诽谤、骚扰他人 | 举报 |
| 违法内容 | 色情、暴力、政治敏感 | 敏感词自动拦截 |
| 恶意刷屏 | 短时间内大量重复内容 | 频率检测 |
| 虚假信息 | 故意传播不实信息 | 举报+审核 |

### 惩罚措施

| 措施 | 说明 | 时长 |
|------|------|------|
| 警告 | 系统通知警告 | — |
| 内容删除 | 删除违规内容 | 永久 |
| 禁言 | 禁止发帖和评论 | 1h / 24h / 7d / 30d |
| 封号 | 禁止登录 | 临时 / 永久 |
| IP 封禁 | 禁止从该 IP 访问 | 临时 / 永久 |

### 申诉机制

被封禁/禁言的用户可通过申诉渠道提出复审请求。

## 审核日志

所有审核操作记录在 `audit_logs` 表中：

- 操作人 ID
- 目标类型和 ID
- 操作类型（通过/拒绝/删除/封禁）
- 操作原因
- 操作时间
- 操作前后状态快照
